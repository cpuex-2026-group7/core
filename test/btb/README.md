# BTB 単体テスト

Verilator と C++ ビルド環境がある WSL/Linux で、リポジトリ直下から実行します。

```sh
make -C test/btb
```

成功すると `PASS: BTB (... checks)` が表示されます。不一致やタイムアウトは
`$fatal` で異常終了します。波形は `test/btb/btb.vcd` に出力します。

`test_btb.sv` の `initial` がテストの手順です。`apply_cycle` で同期入力を
立ち下がりに設定し、次の立ち上がりで DUT に取り込ませます。
`check_lookup` は PC を設定し、2回の立ち上がり後に F2 の応答を期待値と比較します。
BTB 内で、1回目の立ち上がりに PC を F1 レジスタへ取り込み、2回目に検索結果を
F2 の応答レジスタへ取り込みます。毎クロック新しい PC を受け付けられます。
別ポート `resp_F0` は F1 に登録した PC の検索結果を、F2 の応答レジスタを通さず
F0 へフィードバックします。ポート名の F0 は戻し先の段を表します。
入力 PC を設定して1回目の立ち上がり後にヒットの有無 (`valid`) と予測先 (`target`)
が返り、2回目の立ち上がり後に同じ結果が `resp` に返ります。ミス時は両フィールドが0です。
`stream_cycle` では毎クロック PC を変更し、連続する応答の対応関係を確認します。
`!==` による比較で、未確定値 X も失敗として検出します。

確認する動作:

- 初回リセットと、登録済みの全エントリのリセット
- 更新無効時の未登録・既存エントリの保持
- 登録、ヒット、未登録 index のミス、タグ不一致
- 異なる index の独立性
- 同じ PC の分岐先の更新
- 同じ index の別タグによる置き換え
- 全 index の登録と読み出し（分岐先 0 を含む）
- リセットと更新が同時のときのリセット優先
- リセット後の再登録
- F0 から F2 への2段レイテンシと、毎クロックの連続読み出し
- F1 から F0 へのフィードバック（ヒット・ミス・タグ不一致・更新・リセット）
- 入力 PC がクロックエッジ間で変化しても F1 のフィードバックと F2 の応答に影響しないこと
- クロックエッジ間での応答の保持
- 応答登録と同じエッジで同一エントリを更新した場合、更新前の値を返すこと
- リセット時の応答および処理中の要求の破棄
- `update_validness=0` の更新によるエントリの無効化
- `en=0` の間の F1 の PC と F2 の応答の保持、および再開後の進行
